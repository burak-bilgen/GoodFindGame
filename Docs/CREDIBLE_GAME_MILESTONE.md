Pricing reproduction: a condition-100 Vista monitor has base/fair value 5,200, formatted as $5,200 in English and ₺5,200 in Turkish. A stubborn 1.7× ask can reach $8,840 before trends. This is not floating-point overflow: catalog values have no canonical currency/tier, and formatting substitutes symbols without conversion. Condition ≤1, bounded ±12% trends and repair restoration do not explain the order-of-magnitude error. No rarity multiplier exists. Ranked hypotheses: (1) unlabeled catalog values displayed as USD (confirmed by clean-item reproduction), (2) currency formatter substitutes symbols (confirmed), (3) multiplicative inflation (bounded formulas rule it out as primary cause).

## Decisions

Market region is selected on a new save from locale and then immutable in V1; display currency can change without repricing inventory. Language changes only text. A different regional market requires a separate new game rather than an arbitrage switch. Internal rates are fictional versioned balance, never current FX advice. Lightweight market memory uses only actual completed sales, otherwise says insufficient history. No invented recent-sales analytics.

Game Center, ads/payments, auctions, backend, new categories and rare-variant expansion remain deferred.
